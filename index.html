Stakeholders y Requerimientos

Identifica a los interesados de un proyecto y comprende la diferencia entre lo que el sistema debe hacer y cómo debe hacerlo.

¿Qué es un Stakeholder?

Un stakeholder (interesado) es cualquier persona, grupo u organización que puede afectar o ser afectado por un proyecto de software. No solo son los usuarios finales: también incluye a quienes toman decisiones, financian, desarrollan o reciben el impacto del sistema.

Clasificación de los Stakeholders

Internos

Pertenecen a la organización que desarrolla o solicita el proyecto: gerentes, desarrolladores, analistas y patrocinadores.

Externos

No pertenecen a la organización, pero se ven afectados: clientes, proveedores, entidades reguladoras y la competencia.

Primarios y Secundarios

Los primarios usan el sistema directamente (usuarios finales); los secundarios tienen interés indirecto (auditores, soporte técnico).

Requerimiento Funcional (RF)

Un requerimiento funcional describe qué debe hacer el sistema: una acción, tarea o función concreta que el software debe ejecutar para satisfacer una necesidad del usuario.

Ejemplo

"El sistema debe permitir al usuario registrarse ingresando nombre, correo y contraseña."

Requerimiento No Funcional (RNF)

Un requerimiento no funcional describe cómo debe comportarse el sistema: calidad, rendimiento, seguridad, usabilidad o disponibilidad, en lugar de una función específica.

Ejemplo

"El sistema debe responder a cualquier consulta del usuario en menos de 2 segundos."

Requisitos No Funcionales (RFN)

RFN ¿Qué es? Ejemplo
Rendimiento La velocidad del sistema. La app debe cargar en 2 segundos.
Seguridad Proteger los datos contra ataques. Las claves deben estar encriptadas.
Usabilidad Qué tan fácil es de usar. Comprar en menos de 3 clics.
Accesibilidad Uso para personas con discapacidad. Soporte para lectores de pantalla.
Disponibilidad Tiempo que el sistema está activo. Funcionando el 99.9% del tiempo.
Escalabilidad Capacidad de crecer con más usuarios. Aguantar miles de usuarios al tiempo.
Mantenibilidad Facilidad para corregir errores. Arreglar un fallo en menos de 4 horas.
Portabilidad Funcionar en diferentes dispositivos. Sirve en PC, Celular, Chrome y Edge.
Compatibilidad Integración con otros sistemas. Conectarse con la pasarela de pagos.
Confiabilidad Que trabaje bien y sin fallos. Que no pierda datos si se apaga.
Restricciones tecnológicas Límites o reglas técnicas obligatorias. Usar Node.js y React obligatoriamente.
